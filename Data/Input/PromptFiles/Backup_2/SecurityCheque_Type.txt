Business Meaning:
The Guarantee/Security instrument classification.

Where To Search (Priority Order):
1. Work Order content
2. Payment Terms
3. Security Type description
4. Document Title
5. Subject
6. Security Cheque Heading

9. Verification Letter

Return:

PG = Performance Guarantee / Performance Security Cheque
RG = Retention Guarantee / Retention Security Cheque

Rules:

- For Security Cheques, determine the Guarantee Type primarily from the related Work Order and Payment Terms.
- If the Work Order mentions "Advance BG", "Advance Guarantee", "Advance Security", or advance payment secured by cheque, return AG.

- If the document is identified as a Manager's Cheque or Managers Cheque, return MC.
- Use the document title only when it explicitly specifies the guarantee type.
- If both the cheque document and Work Order are available, prioritize the Work Order classification.
- If multiple guarantee types are mentioned, select the type associated with the Security Cheque being submitted.
- If no confident match exists, return null.

DAYS TO EXPIRY

Business Meaning:

The number of calendar days remaining from the current processing date until the Expiry date.

Formula:

DaysToExpiry = Expiry − CurrentDate

Rule:

- Use the current processing date (the date the document is being processed, not a date found in the document) as the starting point.
- Compute the difference in whole calendar days between Expiry and the current processing date.
- If Expiry is in the future, return a positive integer.
- If Expiry has already passed, return a negative integer (do not return 0 or clamp to 0 — a negative value signals the guarantee has already lapsed).
- If Expiry is null or cannot be parsed, return null for DaysToExpiry.
- Return an integer only — no decimals, no "days" unit text.

Example:

CurrentDate = 07-Sep-2026
Expiry = 22-Sep-2026
DaysToExpiry = 15

Example (expired):

CurrentDate = 07-Sep-2026
Expiry = 01-Aug-2026
DaysToExpiry = -37

A couple of things worth deciding before I drop this into your files:

1. **Negative vs. null vs. zero for expired guarantees** — I defaulted to returning a negative number so downstream logic can flag "already expired," but if your system expects `0` or a status flag instead, let me know and I'll adjust.
2. **Which file(s) should get this?** Your OUTPUT FORMAT blocks in both SecurityCheque_Type_Optimized.txt and GuaranteeLetter_Type_Optimized.txt already have a `"DaysToExpiry": null` key sitting in ExtensionData with no corresponding rule section — so this fills a real gap in both. Want me to insert it into both files now?

SECURITY PERCENTAGE

Business Meaning:

The single percentage of contract value covered by this Security Cheque, matching whichever SecurityType was determined for the document.

Where To Search:

Payment Terms
Security Clauses
Retention Clauses

Rule:

First determine SecurityType (Advance / Retention / Performance / SecurityCheque) using the Key Trigger Phrases.
Locate the percentage stated in that same matched clause only — ignore percentages belonging to any other clause in the document.
If the clause breaks the percentage into sub-components (e.g., "50% Advance... 40% on delivery, 10% on installation"), return the headline percentage only, not a sub-component.
If the matched clause states an explicit percentage — including 0 or 0.00% — return that number as-is.
If the matched clause is marked NA or has no percentage stated, return null.
Return one numeric value only — no "%" symbol, no array, no per-type breakdown.

Examples:

Document classified as SecurityType = AdvanceSecurityCheque, clause reads "50% Advance against security cheque" → SecurityPercentage = 50

Document classified as SecurityType = RetentionSecurityCheque, clause reads "0.00% Retention will be applied on each payment" → SecurityPercentage = 0

Document classified as SecurityType = PerformanceSecurityCheque, clause reads "Performance BG/Guarantee Cheque: % of the Work Order Value... NA" → SecurityPercentage = null
